Rigveda AI · Roadmap

A personal AI built on your own files

You pick a folder. Rigveda reads the documents, slides, images, audio and video in it, answers questions about them, and suggests answers while you fill in forms in the browser.

Decisions so far

Decided

Fully local

Parsing, transcription, search and the AI model all run on this machine (RTX 5090, 32 GB VRAM) through Ollama and Whisper. No document text leaves the computer.

Decided

Browser forms first

Suggestions appear through a Chrome extension. A desktop-wide hotkey popup may come later; Ubuntu's Wayland session doesn't let one app read another app's text fields.

How it fits together

Is this RAG? Partly. Answering questions about your files is retrieval-augmented generation (RAG): find the relevant pieces, then let the AI answer from them.

RAG alone is a poor fit for forms. A form field needs an answer in a fraction of a second, and an exact one, since a passport number can't be paraphrased. So Rigveda also builds a personal facts profile: facts are pulled out of documents once, at indexing time, you approve them, and form suggestions become a quick lookup.

1. Every file type becomes text

Each piece keeps its location (page, slide or timestamp) so answers can point to the exact spot. A file watcher re-indexes changed files in the background.

2. Search by words and by meaning

  • Keyword search (SQLite FTS5) for exact terms like names and ID numbers.
  • Meaning search: embeddings from bge-m3, which handles many languages, stored with sqlite-vec.
  • The two result lists are merged, so a loosely worded question still finds the right file.
  • Everything stays in one SQLite file, with no separate database server.

3. Answers

  • qwen3:14b, or qwen3:32b (which fits in 32 GB), for chat answers with citations.
  • qwen3:4b for fast jobs like matching a form field to a fact.

4. Personal facts profile

  • While indexing, the AI scans likely documents (IDs, resumes, bills, letters) and pulls out facts like full_name, date_of_birth, address.current, passport.number and employer, each with its source file and page.
  • Facts stay pending until you approve or edit them on a review page. Only approved facts are suggested.
  • Conflicting facts, such as two addresses, keep their dates, so the newest is preferred and older ones are still visible.

5. Chrome extension for forms

  • When you click into a field, the extension reads its label, placeholder and nearby text to work out what it's asking for.
  • Your local server returns up to 3 suggestions, each showing which file it came from.
  • Tab accepts a suggestion and Esc dismisses it. A "Fill this form" button fills every field it can for you to review. It never submits a form.
  • Later: suggestions while writing longer text, such as cover letters or "describe your experience" boxes.

Security. A server running on your computer can be reached by any web page you visit.

  • Every request needs a secret token, which you paste into the extension once. Without it, any website could query the server and read your documents.
  • The server only accepts requests from the extension and only listens on 127.0.0.1.
  • Password, card number and CVV fields are never touched. There's an off switch for each site.
  • The index holds sensitive text, so it lives in ~/.local/share/rigveda, readable only by you.

Phases

  1. FoundationSplit the code into modules, add tests, fix .gitignore, and add a config file for the watched folder.
    Done when tests pass and indexing behaves as before.
  2. Read every file typePDF, PowerPoint, Excel, image, audio and video support, plus the file watcher.
    Done when a video and a slide deck are searchable, with timestamp and slide citations.
  3. Search by meaningEmbeddings, merged ranking and better chat answers.
    Done when a loosely worded question finds the right file.
  4. Facts profileFact extraction and a review page.
    Done when your name, date of birth, address and IDs appear for approval with their source.
  5. Form autofillThe /suggest endpoint with token security, plus the Chrome extension.
    Done when a test form gets correct suggestions you accept with Tab.
  6. Writing helpSuggestions inside longer text boxes, and an optional desktop hotkey popup.
